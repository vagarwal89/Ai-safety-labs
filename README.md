# AI Safety Labs

End-to-end technical AI safety program: from raw data to deployed-model governance — all with code.

## The journey
| Lab | Topic | Proves |
|-----|-------|--------|
| 01 — Data prep | MinHash dedup, Presidio PII scan, BPE tokenizer, datasheet | You know what models train on |
| 02 — Pre-training | Train nanoGPT, ablation study | You've trained a model |
| 03 — SFT | QLoRA instruction tuning + rubric | You can post-train |
| 04 — RLHF/DPO | Reward model + reward-hacking gallery | You understand alignment failure |
| 05 — Evals | lm-eval-harness + custom eval | You test like a lab |
| 06 — Red-teaming | Adversarial harness + safety report | You break models systematically |
| 07 — RAG | Pipeline + injection attack/defense | You know enterprise AI risk |
| 08 — Fairness | Counterfactual probes + assessment | You measure bias, not just discuss it |
| 09 — Privacy | Memorization tests + PII eval | You govern training data |
| 10 — Safety case | Full safety case + release gate | You govern releases |

## Rules
1. Every claim traces to something run, not read.
2. Each lab ends with a 3-line interview version: what I did, what I found, why it matters.
3. Dangerous-capability work stays conceptual and defensive.
